## Введение

В основе цифрового мира лежит информация, представленная в виде данных. Каждый файл на нашем компьютере — будь то документ, фотография или программа — это набор кодов, занимающий определенное пространство. С ростом объемов этой информации остро встает вопрос: как хранить и передавать ее максимально эффективно? Ответ на него дает целая наука — теория сжатия данных, практическим воплощением которой стал такой привычный и повсеместно используемый формат, как ZIP.

Формат ZIP — это не просто удобный контейнер для файлов, а практическая реализация нескольких ключевых алгоритмов сжатия данных без потерь. Понимание этих алгоритмов позволяет осознанно выбирать инструменты и предсказывать эффективность архивации для разных типов данных.

## Алгоритм Deflate

Формат **ZIP** стал стандартом архивирования именно благодаря алгоритму **Deflate**, созданному **Филом Кацом (Phil Katz)** в конце 1980-х годов.  
Deflate — это **гибридная модель**, объединяющая два классических метода сжатия данных:

1. **LZ77 (Lempel–Ziv 1977)** — устраняет повторы в потоке данных;
2. **Huffman Coding** — кодирует получившиеся символы короткими битовыми последовательностями.

Deflate не теряет данных и обеспечивает высокую степень сжатия для текстов, таблиц, JSON, XML, исходного кода и других структурированных файлов.
Алгоритм Deflate работает поэтапно. Сначала он ищет повторы в данных (LZ77), затем упаковывает найденные шаблоны максимально короткими кодами (Huffman). Рассмотрим оба этапа.
### Этап 1: Поиск повторений (LZ77)

Первым шагом Deflate проходит по потоку данных и ищет **повторяющиеся последовательности байт**.  
Для этого используется **скользящее окно** — область фиксированного размера, в которой алгоритм запоминает недавние данные.

Когда Deflate встречает фрагмент, который **уже встречался ранее** в окне, он **не записывает его снова**, а создаёт ссылку вида:

`<length, distance>`
	
где:
- distance — насколько нужно «отмотать назад»;
- length — сколько символов скопировать оттуда.
Ниже — учебная реализация упрощённого LZ77 на языке 1С:Элемент. Она не оптимизирована, но показывает основной принцип алгоритма.
### Пример на 1С:Элемент
```
// --------------------------------------------------------------
//  УПРОЩЁННАЯ РЕАЛИЗАЦИЯ LZ77 (СЖАТИЕ + РАЗЖАТИЕ)
// --------------------------------------------------------------

// Основная процедура - точка входа в программу
метод Скрипт()
    // ТЕСТОВЫЕ ДАННЫЕ: строка с явными повторениями "ТЕСТ"
    знч Вход = "ТЕСТаьдзрТЕСТваивыраТЕСТ"

    // ВЫПОЛНЯЕМ СЖАТИЕ: преобразуем строку в массив токенов
    знч Сжатое = СжатьДанные(Вход)
    Консоль.Записать("Результат сжатия:")
    // ВЫВОДИМ КАЖДЫЙ ТОКЕН сжатых данных
    для Элемент из Сжатое 
        Консоль.Записать(Элемент)
    ;

    // ВОССТАНАВЛИВАЕМ исходные данные из сжатого формата
    знч Восстановлено = Распаковать(Сжатое)
    Консоль.Записать("")
    Консоль.Записать("Результат распаковки:")
    Консоль.Записать(Восстановлено)
;


// --------------------------------------------------------------
//  СЖАТИЕ
// Преобразует строку в последовательность токенов двух типов:
// - "Литерал: X" - одиночный символ
// - "Ссылка: смещение,длина" - ссылка на повторяющуюся последовательность
// --------------------------------------------------------------
метод СжатьДанные(ВходныеДанные: Строка): Массив<Строка>

    // МАССИВ РЕЗУЛЬТАТА: будет содержать токены сжатия
    знч Результат = новый Массив<Строка>()
    знч Длина = ВходныеДанные.Длина()
    пер Позиция = 0  // ТЕКУЩАЯ ПОЗИЦИЯ обработки в исходной строке
    знч РазмерБуфера = 256  // РАЗМЕР СКОЛЬЗЯЩЕГО ОКНА: сколько предыдущих символов учитываем при поиске
    
    // ОСНОВНОЙ ЦИКЛ ОБРАБОТКИ: проходим по всем символам строки
    пока Позиция < Длина 
        
        // ПЕРЕМЕННЫЕ ДЛЯ ПОИСКА НАИЛУЧШЕГО СОВПАДЕНИЯ:
        пер МаксДлина = 0      // максимальная длина найденного совпадения
        пер ЛучшееСмещение = 0 // смещение до начала лучшего совпадения
        
        // ТЕКУЩИЙ СИМВОЛ для которого ищем повторы
        знч ТекСимвол = ВходныеДанные.Символ(Позиция)
        
        // ОПРЕДЕЛЯЕМ ГРАНИЦЫ ОКНА ПОИСКА:
        // - Начало: либо 0, либо (текущая позиция - размер буфера)
        // - Конец: предыдущий символ от текущей позиции
        знч НачалоПоиска = Макс(0, Позиция - РазмерБуфера)
        знч КонецПоиска = Позиция - 1

        // ПЕРЕБОР ВСЕХ ВОЗМОЖНЫХ ПОЗИЦИЙ В ОКНЕ ПОИСКА:
        // Идём ОТ КОНЦА К НАЧАЛУ (от ближайших позиций к дальним)
        для Смещение = КонецПоиска вниз по НачалоПоиска

            // БЫСТРАЯ ПРОВЕРКА: если первые символы не совпадают - пропускаем
            если ВходныеДанные.Символ(Смещение) != ТекСимвол
                продолжить
            ;

            // ИЗМЕРЕНИЕ ДЛИНЫ СОВПАДЕНИЯ:
            // Начинаем с 1 (первый символ уже совпал)
            пер ДлинаСовпадения = 1

            // ПОСИМВОЛЬНОЕ СРАВНЕНИЕ последующих символов:
            // Сравниваем пока не достигнем конца строки И символы совпадают
            пока (Позиция + ДлинаСовпадения < Длина) и 
                  (ВходныеДанные.Символ(Смещение + ДлинаСовпадения)
                     == ВходныеДанные.Символ(Позиция + ДлинаСовпадения))
                ДлинаСовпадения = ДлинаСовпадения + 1
            ;

            // ОБНОВЛЕНИЕ НАИЛУЧШЕГО СОВПАДЕНИЯ:
            // Если нашли более длинное совпадение - обновляем
            если ДлинаСовпадения > МаксДлина 
                МаксДлина = ДлинаСовпадения
                ЛучшееСмещение = Позиция - Смещение  // вычисляем смещение назад
            // ЕСЛИ ДЛИНЫ РАВНЫ: выбираем совпадение с МЕНЬШИМ смещением
            // (ближе к текущей позиции - эффективнее для сжатия)
            иначе если (ДлинаСовпадения == МаксДлина) и (Позиция - Смещение < ЛучшееСмещение)
                ЛучшееСмещение = Позиция - Смещение
            ;
            
            // ОПТИМИЗАЦИЯ: если нашли очень длинное совпадение - прекращаем поиск
            // (это эвристика для ускорения работы)
            если МаксДлина > 32
                прервать
            ;
            
        ; // конец цикла по позициям в окне поиска

        // ФОРМИРОВАНИЕ РЕЗУЛЬТАТА ДЛЯ ТЕКУЩЕЙ ПОЗИЦИИ:
        
        // ЕСЛИ НАШЛИ ХОРОШЕЕ СОВПАДЕНИЕ (длина > 2):
        // сохраняем ССЫЛКУ вместо самих данных
        если МаксДлина > 2
            // Формат: "Ссылка: смещение,длина"
            Результат.Добавить("Ссылка: $ЛучшееСмещение,$МаксДлина")
            // ПРОПУСКАЕМ всю совпавшую последовательность
            Позиция = Позиция + МаксДлина
        иначе
            // ЕСЛИ СОВПАДЕНИЙ НЕТ ИЛИ ОНИ СЛИШКОМ КОРОТКИЕ:
            // сохраняем символ как ЛИТЕРАЛ
            Результат.Добавить("Литерал: " + ТекСимвол)
            // переходим к следующему символу
            Позиция = Позиция + 1
        ;
    ; // конец основного цикла обработки

    возврат Результат
;


// --------------------------------------------------------------
//  РАСПАКОВКА
// Восстанавливает исходную строку из массива токенов сжатия
// Обратный процесс к сжатию - должен дать исходные данные
// --------------------------------------------------------------
метод Распаковать(СжатыеДанные: Массив<Строка>): Строка

    // БУФЕР ДЛЯ ВОССТАНОВЛЕННЫХ ДАННЫХ: накапливаем результат
    пер Результат = ""
    
    // ОБРАБАТЫВАЕМ КАЖДЫЙ ТОКЕН в сжатых данных
    для Элемент из СжатыеДанные
        
        // ОПРЕДЕЛЯЕМ ТИП ТОКЕНА по началу строки:
        
        // ЕСЛИ ЭТО ЛИТЕРАЛ: просто добавляем символ к результату
        если Элемент.НачинаетсяС("Литерал: ")
            // После "Литерал: " идёт сам символ
            // "Литерал: " имеет длину 9 символов, поэтому берём подстроку с 9-й позиции
            знч Символ = Элемент.Подстрока(9) // длина "Литерал: " = 9
            Результат = Результат + Символ

        // ЕСЛИ ЭТО ССЫЛКА: копируем данные из уже восстановленной части
        иначе если Элемент.НачинаетсяС("Ссылка: ")
            // После "Ссылка: " идут два числа через запятую: смещение и длина
            знч Остаток = Элемент.Подстрока(8) // длина "Ссылка: " = 8
            
            // ПАРСИМ ЧИСЛА: находим запятую-разделитель
            знч ПозицияЗапятой = Остаток.Найти(",")

            // ЗАЩИТА ОТ ОШИБОК: если формат неправильный - пропускаем
            если ПозицияЗапятой < 0 
                продолжить // защита от ошибок формата
            ;

            // ИЗВЛЕКАЕМ ЧИСЛА из строки:
            // - смещение: от начала до запятой
            // - длина: после запятой до конца
            знч Смещение = новый Число(Остаток.Подстрока(0, ПозицияЗапятой))
            знч Длина = новый Число(Остаток.Подстрока(ПозицияЗапятой + 1))

            // КОПИРОВАНИЕ ПОСЛЕДОВАТЕЛЬНОСТИ:
            // Смещение указывает, на сколько символов НАЗАД нужно вернуться
            // от конца текущего результата
            знч Начало = Результат.Длина() - Смещение
            
            // КОПИРУЕМ указанное количество символов
            для i = 0 по Длина - 1 
                // Берём по одному символу из уже восстановленных данных
                знч Символ = Результат.Подстрока(Начало + i, Начало + i + 1)
                Результат = Результат + Символ
            ;
        ;
    ;
    возврат Результат
;
```

> [!NOTE] Вывод
> 
> LZ77 убирает избыточность — повторяющиеся фрагменты заменяются короткими ссылками. Можно сказать, что LZ77 записывает не весь текст заново, а просто указывает: «возьми тот же фрагмент, что был чуть раньше». Именно поэтому повторяющиеся данные (логи, шаблоны, XML) сжимаются особенно хорошо. Например:
> 
> Исходная строка: 
> `"Ошибка соединения. Ошибка соединения. Ошибка соединения!"`
> 
После работы LZ77 она может превратиться в нечто вроде: 
`Ошибка соединения. <22,22> <22,22>!`
>
Здесь <22,22> означает: «вернись на 22 символа назад (до начала предыдущей фразы) и скопируй 22 символа оттуда».
То есть ZIP не хранит трижды одинаковый текст, а просто указывает, откуда его можно взять.

### Этап 2: Энтропийное кодирование (Huffman Coding)

После удаления повторов остаётся поток символов и ссылок `<length, distance>`.  
Теперь Deflate применяет **кодирование Хаффмана**, чтобы представить этот поток **в битовом виде**, максимально компактно.

Принцип прост:

- символы, которые встречаются часто, получают **короткий код**;
- редкие — **длинный код**.

#### Пример 

Представим, что после LZ77 остался следующий поток: `ОК, ОК, ОК, Ошибка, ОК, Ошибка`
Частоты:

|Элемент|Частота|Код|
|---|---|---|
|"ОК"|66%|`0`|
|"Ошибка"|33%|`10`|

Поток превращается в: `0 0 0 10 0 10`
Вместо 36 символов текста — всего 8 бит информации. Благодаря этому короткие коды занимают меньше места, а общая длина потока уменьшается.

### Пример на 1С:Элемент

```
// --------------------------------------------------------------
//  Демонстрация Энтропийного кодирования (Хаффман)
// --------------------------------------------------------------
метод Скрипт()
    // Исходная строка для кодирования
    // В этой строке символы повторяются с разной частотой
    знч ИсходнаяСтрока = "AAAABBCDDDD"

    // Шаг 1. Подсчёт частот символов
    // Создаём словарь, где ключ = символ, значение = сколько раз символ встречается
    знч Частоты = <Строка, Число>{:} 

    // Проходим по каждому символу строки
    для Символ из ИсходнаяСтрока
        если Частоты.СодержитКлюч(Символ) 
            // Если символ уже есть в словаре, увеличиваем счётчик
            Частоты[Символ] = Частоты[Символ] + 1
        иначе
            // Если символ встречается впервые, создаём запись со значением 1
            Частоты[Символ] = 1
        ;
    ;

    // Выводим частоты символов на консоль
    Консоль.Записать("Частоты символов:")
    для Символ из Частоты.Ключи()
        Консоль.Записать(Символ + " -> " + Частоты[Символ])
    ;

    // Шаг 2. Простейшее кодирование по частоте (демо)
    // Принцип: чаще встречающиеся символы получают короткий код
    // Редкие символы получают длинный код
    пер Отсортированные = Частоты.СортироватьПо(Элемент->Элемент.Значение, НаправлениеСортировки.ПоУбыванию) 
    // сортируем частоты по убыванию (самые частые символы первыми)

    // Создаём словарь для хранения кодов символов
    знч Коды = <Строка, Строка>{:}

    // Начальная "длина кода" для демонстрации
    пер ДлинаКода = 1

    для Символ из Отсортированные
        // Для наглядности используем повторение самого символа для визуализации длины кода
        пер СимволКода = ""
        для i = 1 по ДлинаКода
            // Повторяем символ столько раз, сколько "длина кода"
            СимволКода = СимволКода + Символ.Ключ.Подстрока(0,1) 
        ;
        // Сохраняем код символа в словарь
        Коды[Символ.Ключ] = СимволКода

        // Увеличиваем длину кода для следующего, более редкого символа
        ДлинаКода = ДлинаКода + 1
    ;

    // Шаг 3. Вывод кодов символов
    Консоль.Записать("")
    Консоль.Записать("Коды символов:")
    для Символ из Коды.Ключи()
        Консоль.Записать(Символ + " -> " + Коды[Символ])
    ;

    // Шаг 4. Энтропийное кодирование всей строки
    // Для каждого символа заменяем его на соответствующий код
    пер ЗакодированнаяСтрока = ""
    для Символ из ИсходнаяСтрока
        ЗакодированнаяСтрока = ЗакодированнаяСтрока + Коды[Символ]
    ;

    // Выводим результат кодирования
    Консоль.Записать("")
    Консоль.Записать("Закодированная строка:")
    Консоль.Записать(ЗакодированнаяСтрока)
;

```

B -> 2

D -> 4

Коды символов:

Закодированная строка:

#### Что делает этот код

1. **Считает частоту каждого символа** — показывает, какие символы встречаются чаще.
2. **Присваивает коды разной длины** в зависимости от частоты: часто встречающиеся символы — короткие, редкие — длинные.
3. **Заменяет символы на коды**, показывая, как данные можно "сжать" с помощью энтропийного кодирования.
4. **Наглядная демонстрация** — повторение символов иллюстрирует длину кода и принцип Хаффмана без битов.

В данном примере строка результата визуализирует только длину кодов, а не реальное сжатие. В настоящем кодировании Хаффмана вместо длинных символов используются биты, поэтому итоговый размер действительно уменьшается.
#### Два дерева Хаффмана

Deflate использует **два дерева Хаффмана**:

1. Для **литералов и длин** (`length`) — то есть для самих символов и длины повторов.
2. Для **расстояний** (`distance`) — чтобы кодировать, насколько далеко нужно отмотать назад.

Оба дерева **динамически перестраиваются** под каждый блок данных — это значит, что ZIP адаптируется к тому, что именно находится в файле.  
Например, JSON с повторяющимися ключами будет сжат иначе, чем бинарный лог.

#### Почему это важно  

Алгоритм Хаффмана позволяет добиться максимальной эффективности — часто встречающиеся элементы занимают меньше места. Благодаря этому ZIP остаётся универсальным и быстрым даже спустя десятилетия.

> [!NOTE] Вывод
> 
> - Huffman coding переводит поток ссылок и символов в компактные двоичные коды.
> - Чем чаще встречается элемент — тем меньше места он занимает.
> - Deflate подстраивается под тип данных, обеспечивая оптимальное сжатие даже на разных типах файлов.
> 
> Deflate — пример того, как простые идеи, объединённые в одну систему, могут десятилетиями оставаться актуальными. Понимание таких алгоритмов помогает лучше проектировать хранение данных и писать более эффективный код.


## Заключение

Алгоритмы сжатия в ZIP демонстрируют элегантное сочетание теоретических концепций компьютерных наук с практическими потребностями обработки данных. Понимание работы LZ77 и кодирования Хаффмана позволяет не только эффективно использовать существующие инструменты архивации, но и создавать оптимизированные решения для специфических задач обработки данных в системах на платформе 1С.

Ключевые преимущества алгоритма Deflate:

- Адаптивность к разным типам данных
- Быстрое распаковка
- Хороший баланс между скоростью и степенью сжатия
- Простота реализации

Эти характеристики делают ZIP и его алгоритмы сжатия незаменимыми инструментами в арсенале современного разработчика.
